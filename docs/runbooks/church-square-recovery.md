# Church Street Square event recovery

Square's production notification receiver acknowledges an accepted event after it is stored. The event kicks a bounded recovery worker. A manager can also retry by loading the reconciliation view. The scheduled job makes another attempt when the café is quiet.

The Supabase job `le-yard-church-square-retry` runs every five minutes. It calls Operations with a short-lived proof derived from the dedicated signing key stored in Vercel Production and Supabase Vault. The proof expires after 90 seconds. The key itself does not enter the outgoing request, logs, or application database tables. The endpoint accepts one bounded refresh and returns an empty 202. Receipt leases prevent concurrent processing of the same event, and durable state prevents an older Square version from overwriting a newer one.

The platform setup is in [church-square-recovery-schedule.sql](sql/church-square-recovery-schedule.sql). Apply only to the production Operations database after verifying the linked project. The deployment needs `LE_YARD_CHURCH_SQUARE_RECOVERY_SECRET` in the Operations server's Production environment and the identical value in Vault under `le_yard_church_square_recovery_v1`. Keep the key out of the SQL file. The worker also uses the existing scoped Square order-read configuration.

Check the cron job's run status and the corresponding HTTP status in net._http_response, without selecting request headers or payloads. A 202 confirms the route accepted the trigger. Check the receipt processing status or the manager's reconciliation panel to tell whether work succeeded. If the queue still grows, verify Square credentials, exact location, provider rate limits and review status. To suspend scheduled retries, set the named job inactive in Supabase Cron. Event-driven and manager retries continue.

Each scheduled run also reads Square's current `IN_STOCK` counts for the enabled Church Street mappings when the existing production count connection is enabled. The stock pass keeps the provider's calculation time and applies newer observations through the same low-stock rules as the signed webhook. A missing row leaves the last observation in place. Verify the stock pass in the Operations runtime log using `Church Street Square stock checked.` and its `mapped`, `observed`, `applied`, and `ignored` counts. `Church Street Square stock check incomplete.` identifies a failed stage and the next scheduled run retries the read. The pass records no physical count and cannot reconstruct a stock crossing that began and ended between successful observations.

The same signed trigger also runs an independent, bounded SearchOrders pass when `LE_YARD_CHURCH_SQUARE_ORDER_BACKFILL_ENABLED=true` on Operations Production. It filters by the verified café location and Square's update timestamp. The order coverage time advances after every page in a window is checked and saved. When a window cannot finish, the next pass rechecks it without dropping the unchecked period. Square only returns records available at its server. Compare native POS, marketplace and Square pickup behavior before treating the feed as a courier or ticket authority.

Reconciliation shows the last completed order coverage time once the first pass succeeds. That timestamp is for the order read. Payment, refund and invoice event retries continue independently. A 202 from the trigger confirms dispatch only. If coverage stops advancing, inspect the private Church order backfill state, platform logs and the Square API logs before adjusting the cursor.

Today’s **Square pickup and delivery watch** reads the order facts already saved in Operations. It refreshes while Today is visible and shows the latest completed recovery coverage separately from the current Operations read. The watch checks orders updated in the past 24 hours and lists up to 50 with pending pickup or delivery. Start times describe the provider’s scheduling window. Compare prep, readiness and actual handoff against the staffed Square ticket and the delivery partner’s own status. If recovery is missing or behind, use those surfaces while checking the event worker and backfill.
