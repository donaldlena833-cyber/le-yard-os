# Church Street catering website intake

Operations Catering shows incoming requests separately from catering jobs. The request list includes type, preferred date, headcount and status. A Church Street manager with financial reporting access can open a request to see contact and event details and create an inquiry job after choosing a service date. Conversion uses the same audited catering-job command and leaves the job at inquiry stage. Attach the correct Square invoice and publish reviewed prep quantities later in the existing workflow.

The Operations POST route is `/api/v1/church-catering-inquiries`. It uses a dedicated SHA-256 key digest in `catering_private.catering_api_clients` bound to the active Church Street location. The private client starts inactive. The route requires `LE_YARD_CHURCH_CATERING_RECEIVER_ENABLED=true`. The website route is `/api/church-catering-inquiries` and uses its own `LE_YARD_CHURCH_CATERING_INTAKE_ENABLED`, `_URL`, `_KEY`, and `_OWNER` server settings. The production relay needs an HTTPS URL whose exact path is the Church Street receiver. Set the owner to the person responsible for handling the requests. Configure the caller secret in the website host and store only its digest in the database.

Rehearse with the separate Church routes on isolated infrastructure. Verify the same UUID and brief return the original committed receipt, a changed replay fails, and the authorized manager can open and convert just once. Confirm the applicant sees a request acknowledgment and the chosen staff owner knows how to reply. Marketing consent is false. This receiver creates neither a customer profile nor a Square invoice. The Church relay omits the dietary and other-notes fields from the older form contract.

Before enabling public intake, verify the Church Street entry, named owner, private lead retention and staffing. To pause intake, turn off the website relay and the Operations receiver while preserving previous records and staff access. Operations, Host, and Phone share the runtime schema contract and must be compatible with the applied migration.
